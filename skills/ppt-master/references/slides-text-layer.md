# Slides Text Layer

A per-slide text source layer that mirrors `notes/`. Lets users edit slide text without touching SVG layout, and lets the AI regenerate slide text without rebuilding entire SVGs.

## Why this exists

SVG output mixes layout (positions, sizes, colors) with text content. Editing text-only changes previously required either diving into SVG markup or fixing the rendered PPTX after export. This layer separates the two concerns: layout stays in SVG, text becomes editable per-slot.

## Folder

```
<project_path>/
├── svg_output/          ← layout + text (visual source)
├── slides/              ← text-only source layer (this layer)
│   ├── _plan.md         ← project-level planning doc (narrative, transitions, risks, references, …)
│   ├── 01_cover.md      ← per-slide slot:value MDs (auto-generated by slides_extract)
│   ├── 02_toc.md
│   └── ...
└── notes/               ← speaker notes (already exists)
```

Files starting with `_` (e.g., `_plan.md`) are project-level companions. They are
NOT per-slide MDs — `slides_extract.py` / `slides_apply.py` skip them naturally
because they have no matching SVG. Per-slide MDs follow the strict
`<NN>_<name>.md` naming pattern.

## SVG-side: `data-slot` attribute

Every user-facing `<text>` element on a slide carries a `data-slot="..."` attribute that names the slot. Slot paths use dot notation and are unique within a slide.

```xml
<text data-slot="header.title" x="81" y="100" font-family="Poppins, Arial, sans-serif" font-size="43" font-weight="700" fill="#FFFFFF">3DGS: Mathematical Formulation</text>
```

**Rules**:
- Slot path: `[a-zA-Z0-9_.-]+`, dot-separated; first segment usually matches the parent `<g id="...">`
- Unique within a single SVG file (not globally)
- Footer text (`<g id="footer">`) and pure decoration (background, dividers, accent rects) carry no slot
- Text containing `<tspan>` is currently NOT supported — the text element must be flat plain text. Split rich runs into adjacent plain `<text>` elements if you need slots on them.

## slides/*.md format

```markdown
# 12: 3DGS: Mathematical Formulation

> Source: `12_3dgs_math.svg`
> Edit values below, then run: `python scripts/slides_apply.py <project_path>`

## header
header.title: 3DGS: Mathematical Formulation

## equations
equations.eq1.label: WORLD-SPACE DENSITY
equations.eq1.formula: G_i(x) = exp(−½(x−μ_i)ᵀ Σ_i⁻¹(x−μ_i))
equations.eq1.caption: Anisotropic Gaussian in 3D: position μ, covariance Σ
equations.eq2.label: COVARIANCE FACTORIZATION
equations.eq2.formula: Σ_i = R(q_i) · diag(s_i²) · R(q_i)ᵀ
```

**Parser rules** (intentionally minimal):
- Lines matching `<slot.path>: <value>` define a slot — the slot path is `[a-zA-Z0-9_.-]+`
- Markdown headings (`#`, `##`, ...) are visual grouping only; parser ignores them
- Lines starting with `>` are notes / instructions; parser ignores them
- Blank lines: ignored
- Slot value is the rest of the line, trimmed; values are always single-line strings (matches single-line `<text>` content)

## Workflow

### Direction A — text edited in `slides/`
```
1. Edit slides/12_3dgs_math.md
2. python scripts/slides_apply.py <project_path>            # slides/ → svg_output/
3. python scripts/slides_plan_refresh.py <project_path>     # (optional) refresh _plan.md derivable cells
4. python scripts/finalize_svg.py <project_path>
5. python scripts/svg_to_pptx.py <project_path> -s final
```

### Direction B — text edited in SVG
```
1. Edit svg_output/12_3dgs_math.svg
2. python scripts/slides_extract.py <project_path>          # svg_output/ → slides/
3. python scripts/slides_plan_refresh.py <project_path>     # (optional) refresh _plan.md derivable cells
4. (continue downstream as needed)
```

### Plan derivation
`_plan.md` (project-level companion under `slides/`) holds narrative spine,
suggested transitions, risk register, references, etc. Its §4 *Chapter
Structure* table and the Title cells of its §5 *Per-Slide Breakdown* tables
mirror per-slide MD content.

**One-way derive** (slides → plan): `slides_plan_refresh.py` reads `slides/*.md`
and rewrites only those derivable cells. Human-authored cells (Role, Net runtime,
Rhythm, Time, Coverage) and entire prose sections are never touched. The script
also never inserts or deletes rows automatically — it warns on discrepancies
(extra rows in plan, missing rows from slides) and the user resolves manually.
There is **no plan → slides direction**: edits to slot values must go through
`slides/<NN>_<name>.md` then `slides_apply.py`.

### Truth policy

**Last modified wins, sync is always explicit.** No automatic synchronization. The user runs `slides_apply` or `slides_extract` deliberately, with awareness of which side has the latest edits.

The scripts may **warn** (not block) when the destination side has been modified more recently than the source — in that case the user reaffirms direction or runs the opposite direction first.

## Bootstrapping an existing project

For projects whose SVGs were generated before this layer existed:

```
python scripts/slides_init.py <project_path>
```

This script walks `svg_output/`, auto-assigns `data-slot="<g_id>.<index>"` to every plain `<text>` element with a parent `<g id="...">`, skips footer and tspan-bearing texts, and writes the modified SVGs back. Run `slides_extract.py` afterwards to populate `slides/`.

**Idempotent**: text elements that already carry `data-slot` are left untouched.

## When generating new SVGs

Executor: when generating any new `<text>` element, **also include `data-slot`** with a meaningful path. Use `<g id="...">` to namespace slots and a short descriptor for the role (`title`, `subtitle`, `body1`, `caption`, `formula`, `label`). Skip slots only on footer and pure decoration.

Good:
```xml
<g id="metric-card">
  <text data-slot="metric.label" ...>FPS</text>
  <text data-slot="metric.value" ...>134–160</text>
  <text data-slot="metric.unit" ...>at 1080p</text>
</g>
```

Avoid (positional indexes are valid but lose semantic meaning — only use during bootstrap):
```xml
<text data-slot="metric-card.1" ...>FPS</text>
<text data-slot="metric-card.2" ...>134–160</text>
```
